# database-design-project
The database was designed to facilitate the analysis and organization of data from soccer matches. We decided on five tables because they cover the main elements of the system without overcomplicating the database. The teams table stores basic club info. The players table connects each player to a team. The matches table stores important details and the final scores. The match_events table stores key stats such as passes, shots, fouls, turnovers, and cards. Finally, the substitutions table is separate which allows player changes to be looked at more easily. 
All relationships are one to many, as this mimics the actual relationship these events/tables have to each other in the real world. 
The sample data was generated by AI. The first version was missing fields and records so it was manually reviewed and corrected. We only used 3-5 matches and a few teams to keep the project manageable. Having more matches and teams would add a lot of data that are unnecessary for the purpose and stakeholders of the database. Having larger player, event, and substitution tables are much more useful for testing relationships and queries.
